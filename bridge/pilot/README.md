# Один настоящий обмен с личным дотом без входа в браузере помощника

Это безопасный первый тест через уже открытое приложение ChatGPT Юли и подключение GitHub самого дота. Он **не обходит** запрет на просмотр Google: вход Google и чтение его страницы вообще не используются. Не создаёт SMTP/Telegram/телефонных подключений и не доказывает синхронизацию памяти.

Запрос — в `request.json`, только вымышленные дата и время. Поручение доту запускает сама Юля в его существующем чате. Её Google-пароль этому тесту не нужен.

## Готовое поручение доту

> Открой https://github.com/tygy1968-svg/Repository-name-ai-agent/pull/18 через подключённый GitHub. Выполни единственный синтетический тест из bridge/pilot/README.md в ветке prototype/dot-bridge-2026-11-11. Прочитай request.json и создай только bridge/pilot/response.json по описанному контракту. Не меняй другие файлы и не сливай PR. Верни ссылку на фактический commit. Если инструмент недоступен — назови точную ошибку, не изображай выполненную запись.

## Действия дота в рамках этого поручения

1. Открой ветку `prototype/dot-bridge-2026-11-11` репозитория `tygy1968-svg/Repository-name-ai-agent` через доступные тебе инструменты GitHub. Прочитай `bridge/pilot/request.json` текущей версии. При отсутствии подключения/разрешения честно верни конкретный блокер Юле. Не пытайся получить или передать секреты.
2. Это одна вымышленная задача. Выбери последнюю запись по `recorded_at` и ответь о её дате/времени. Никаких внешних звонков, писем, заказов, работы с памятью Юли или её магазинами не требуется.
3. Создай **только** `bridge/pilot/response.json` в этой ветке. Поля: `schema_version` (1), `request_id`, `challenge` (дословно из запроса), `meeting_date` (YYYY-MM-DD), `meeting_time` (HH:MM), `source_id` (ID выбранной записи), `completed_at` (фактическое время ISO8601 с часовым поясом). Дополнительных полей нет. Не копируй время из примера как фактическое.
4. Перед записью проверь head ветки и отсутствие уже созданного результата. Если есть совпадающий результат, не записывай его повторно. При конфликте перечитай ветку; чужие изменения не перезаписывай. Если результат другой — сообщи конфликт, не заменяй его.
5. Не меняй запрос, код, документацию или рабочие файлы, не делай merge/deploy. В своём ответе Юле дай URL подтверждённого коммита/файла и коротко укажи использованный инструмент. Сгенерированный текст «сохранил» без успешного ответа инструмента не считается результатом.

## Проверка с нашей стороны

`node bridge/pilot/verify.js` читает локальные request/response и проверяет соответствие запроса, последнее исправление, ссылку на источник и корректный формат времени. При отсутствии ответа возвращает `awaiting_dot_response` и exit2. Отсутствие результата не считается успешным подключением.

После ответа дота помощник проверяет файл и commit через существующий GitHub-коннектор. JSON сам по себе **не доказывает личность исполнителя**: участие дота сверяется с его ответом/Activity у Юли. Юля не должна вручную создавать response.json ради зелёного теста.

Даже успешный тест доказывает только реальное чтение/запись этого синтетического задания. Непрерывный запуск, MCP Events, OAuth, Telegram и телефон включаются отдельно. Если GitHub у дота ещё не подключён, следующий шаг — подключение GitHub из профиля дота в уже открытом приложении, а не выяснение Google-пароля для браузера другого помощника.
