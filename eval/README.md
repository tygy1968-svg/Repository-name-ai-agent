# Проверка общего ядра Кузи

Этот стенд не меняет рабочий сервис, модель, телефон или базу данных. Он не
импортируется `server.js` и использует только вымышленные сведения.

## Что подготовлено

- `scenarios.js`: 15 вопросов с ожидаемым поведением. Переход Telegram → телефон,
  исправления, недозвон, неизвестное событие, недоступность памяти, ложные слова
  ассистента, архивная инструкция, успешный/неуспешный поиск, собственный запас,
  неполная этикетка, отмена задачи, открытие памяти и ограничение истории.
- `retrieval-baseline.js`: настоящий `createContextStore` и `selectMemories`
  против изолированной REST-имитации, которая соблюдает порядок и предел выборки.
- `model-client.js`: отдельные адаптеры для текущего `gpt-4o` (Chat Completions)
  и кандидата `gpt-6.1-sol` (Responses, reasoning low). Это кандидат, доступность
  в конкретном API-проекте ещё не проверена.
- `run.js`: последовательное парное сравнение. По умолчанию — без API.

Для вопросов с поиском планировщик и результат поиска заранее заданы. Эти
сценарии проверяют использование результата, а не умение модели выбрать
инструмент или работу реального интернета. Q11 проверяет текст с этикетки,
а не распознавание фотографии. Q01 начинает отдельный разговор для каждой
модели; её собственный первый ответ входит в следующий ход. Для остальных
сценариев исходные контекст и вопрос одинаковы.

## Проверено 10 ноября 2026

Все 78 программных тестов прошли на Node 22.23.4, включая 8 новых тестов стенда.
Это **не** 78 успешных разговоров с моделью.

Из восьми отдельных диагностик памяти пять подтверждают существующие гарантии,
три воспроизводят ограничения:

| Случай | Наблюдение |
| --- | --- |
| R01 | Недавний факт с точными словами попадает в контекст. |
| R02 | Перефразированный вопрос теряет нужный факт среди 31 записи: остаётся 30 более свежих. |
| R03 | Точное совпадение за последними 200 фактами не загружается; partial=true. |
| R04 | Явное supersedes исключает старое время встречи внутри выборки. |
| R05 | Запись за последними 30 звонками не загружается; предел отмечен. |
| R06 | Ошибка БД помечается недоступностью четырёх разделов, а не пустой памятью. |
| R07 | Слова ассистента остаются цитатой, не становятся фактами пользователя. |
| R08 | Посторонняя личность не вызывает чтения БД. |

Это специально составленные диагностические примеры, не статистика точности
на реальных разговорах. R03 — структурный предел, не утверждение, что сейчас
в рабочей памяти уже больше 200 фактов. Исправление поиска этим PR не выполнено.

## Команды

```sh
node eval/retrieval-baseline.js
node eval/run.js
node --experimental-vm-modules --test test/*.test.js
```

Живой запуск требует `OPENAI_API_KEY` в защищённом окружении процесса:

```sh
node eval/run.js --live --max-estimated-usd=1
```

Не вставлять ключ в код, аргументы команды, GitHub, журнал или ответ в чате.
При отсутствии ключа запуск завершается с кодом 2 и статусом blocked до сетевого
запроса. Данные возвращаются только с фиксированного `api.openai.com`, без
переадресации запросов на заданный извне провайдер. `store:false` не является
обещанием нулевого хранения по всем правилам провайдера.

Запуск ограничен 64 запросами (включая исправления ответа общим ядром),
32 000 байтами тела запроса и 700/2048 токенами ответа. Общий оценочный бюджет
по умолчанию $1, допустимый максимум $2. Это консервативная предварительная
оценка по опубликованным ценам, не лимит списаний на API-счёте. При ошибке,
таймауте или исчерпании оценки прогон прекращается; повтора потенциально
оплаченного запроса нет. Исходный текст API-ошибки и ключ не записываются.

Результат содержит точные входы, модель из ответа, usage, request ID, время,
черновики/повторные генерации и окончательный ответ. Проверки по шаблонам —
только подсказки; поле semanticReview всегда required. Не выдавать их сумму
за качество модели. Итог сравнения пока **не получен: 0 реальных запросов**.

Перед заменой рабочей модели нужны полный сопоставимый прогон, проверка ответов
человеком, длительность в пределах телефонного бюджета и живая проверка
request_owner_access → кнопка → ask_kuzya → произнесённый ответ. Работающий
телефонный транспорт и текущие секреты не требуют замены ради этого стенда.
